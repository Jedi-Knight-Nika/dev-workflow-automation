# V2.2 native Developer token efficiency

Implemented in the modular monolith; uses the existing application PostgreSQL
database and the existing isolated native runner. Migration: `0004_token_efficiency`.
No new agents, paid forecasting, transcript replay, RAG, or token-reset operation.

## Operator controls

Team pages expose FAST, STANDARD, LARGE and CUSTOM presets, reasoning effort,
instrumentation/warning/enforcement modes and expandable numeric settings. Task
details expose measurements, physical context generations, suspended-task preset
overrides and checkpoint/rollover. Task overrides take precedence over Team policy.
Preset defaults follow the V2.2 proposal. Existing Teams retain their configured
reasoning effort until an explicit token policy is saved.

The default is INSTRUMENT, with native tool-output bounding enabled. WARN sends
one reminder per condition; ENFORCE additionally interrupts for exploration,
unchanged expensive command/check loops, excessive active context, repeated
compaction without progress, and sustained no-progress. No-progress warns at its
soft allowance and stops at twice that allowance. A stopped run does not buy a
replacement run. USD reservations and unknown-cost blocking remain authoritative.

Automatic rollover additionally requires `automatic_rollover=true` and ENFORCE.
It runs at a completed milestone or before resuming oversized review context,
never concurrently with a native turn. Failed checkpoint/acknowledgment or exhausted
rollover allowance stops for operator inspection. LARGE milestones remain inside
one task, checkout and eventual PR. Full offline final validation is unchanged.

## Code ownership

- `agent_runtime/domain/token_efficiency_policy.py`: validated preset policy.
- `agent_runtime/application/developer_progress_governor.py`: provider-neutral
  usage/progress state, warnings and stop decisions. It cannot edit source.
- `agent_runtime/infrastructure/codex.py`, `claude.py`: pinned native event mapping,
  output controls, steering/interruption and capability declarations.
- `agent_runtime/infrastructure/tool_logs.py`: private native-state output archive;
  SHA256/size metadata and a 100 MB task-home allowance. Exhaustion stops capture
  rather than silently discarding evidence. Existing native-state retention owns
  eventual cleanup; logs are not public API payloads.
- `agent_runtime/infrastructure/checkpoints.py`: shell-free, bounded, read-only Git
  inspection, including untracked file content in the workspace fingerprint.
- `agent_runtime/infrastructure/token_efficiency.py`: policy audit/versioning,
  checkpoint/generation persistence, operator guards and task queries.
- `agent_runtime/infrastructure/accounting.py`: associates actual receipts with
  physical generations; live signals never overwrite invoice fields.
- `engineering/infrastructure/executor.py`: lease/budget-controlled boundary
  transitions. Delivery and exact-SHA validation/approval/merge gates are unchanged.

## Continuity protocol

The logical DeveloperSession remains task-owned. A new physical generation keeps
the checkout and native-state directory, seals the old generation, and retains its
native ID. Only the physical thread's cumulative usage baseline is cleared; AIRun
receipts and lifetime spending are retained.

Before sealing, the controller locks the Team/task/session and the task's shared
workspace lock, checks suspended state (or the exact active controller lease),
rejects running/unknown-cost turns, computes Git facts, and persists a digest-checked
checkpoint in the same transaction as the generation transition. JSON is capped
at 5,000 bytes, conservatively within the proposed model-visible token ceiling.
Oversized requirements/feedback/changes must be explicitly reduced; no silent
feedback truncation is used for rollover.

On continuation, the runner rechecks the workspace fingerprint and the controller
meters a read-only acknowledgment turn. The exact checkpoint digest must be
acknowledged before any writable turn is permitted. Missing acknowledgment is not
automatically retried. The subsequent turn is separately budget-admitted, on the
same native thread, with only the current requirement and verified checkpoint.
No old transcript is injected. A failed read-only attempt still retains its receipt.

## Measurement semantics

PostgreSQL AIRun input/output/cache/cost remains invoice truth. Active context is
the latest inference's reported input, explicitly labeled an estimate of what the
next inference carries, not total task input. Claude input includes reported cache
reads/writes; Codex cached input remains a subset, not an extra input category.

Progress uses verified Git fingerprint changes, not `git status`, repeated reads
or model assertions. Tool outcomes and phase attribution are observational estimates.
Native SDK-exposed output bytes are not claimed to be exact model-visible token
counts. Unsupported or historical measurements remain unknown. Historical tasks
do not get fabricated first-edit or active-context values.

Codex uses the stable pinned app-server APIs and `tool_output_token_limit`, not
experimental context management. Claude uses the pinned SDK's tool-result hooks
and Bash/Read limits. Native output deltas/hook results are archived; any truncation
performed inside the upstream CLI before emitting those events cannot be recovered
by the platform. The stable Developer instructions route noisy builds/checks through
`agent_runtime.infrastructure.bounded_command`, which captures full process output,
returns bounded diagnostics and a protected log path, strips credentials from the
subprocess environment, and kills the process group on timeout/cancellation. Native
commands bypassing this wrapper have only the SDK-exposed evidence guarantee.

## HTTP

Canonical paths begin `/api/v2`; existing `/api/v1/v2` clients stay compatible.

- GET `tasks/{id}/token-efficiency`, `context-generations`, `checkpoints`
- GET/PUT `teams/{id}/token-efficiency-policy` (optimistic policy version)
- GET/PUT `tasks/{id}/token-efficiency-policy` (suspended task, lifecycle version)
- POST `tasks/{id}/context-rollover` (requirement version and bounded note)

These use the existing operator-facing ingress boundary. Do not publish the native
state volume or bypass the authenticated production ingress. Local Compose binds
the API/frontend only to loopback; monitoring remains internal.

## Acceptance and rollout

Focused checks cover governor behavior, native SDK schema seams, Git/untracked
fingerprints, byte caps/log retention, real PostgreSQL migrations and physical
generation rollover without invoice mutation. Browser checks cover the Team policy
and task panels at desktop/mobile widths. Docker builds include both the controller
and repository-specific native runner, not just the web UI.

The paid baseline-versus-policy benchmark is a separate rollout gate, not a claimed
result of unit tests. Keep enforcement/automatic rollover opt-in until representative
tasks establish completion reliability and token savings. Do not claim a 50k-token
target, provider-native compaction quality, or lower completed-task cost without
that measured evidence. Repository-specific defaults, deterministic source-label
profile heuristics and provider server-side history clearing can be added without
changing this policy/continuity boundary; they are not enabled by this slice.
